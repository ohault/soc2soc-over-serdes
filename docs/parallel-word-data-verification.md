# Parallel-word DATA transmitter verification

The experimental `bonded_wire_tx_lane_parallel` now has two independent
regressions:

- A 32-bit single-beat golden-vector test that holds the first output word
  under backpressure and checks output stability.
- A multi-beat test that constructs the expected v0 frame independently,
  including header CRC-16 and frame CRC-32C, then compares every emitted byte.

The multi-beat test is parameterized and the CI workflow elaborates/runs it at
8, 16 and 32 bits. It sends a seven-byte payload, which exercises full and
partial final input words at all three widths, and varies output READY to
exercise stalls while the frame is being emitted.

The transmitter latches the packet length at admission and checks the
cumulative payload byte count before accepting the final beat. The byte-serial
transmitter remains the protocol reference; the new tests currently use an
independently generated byte stream rather than replacing or modifying that
reference.

## Cross-implementation interoperability regressions

Three connected testbenches now cover the important encoder/decoder pairings:

- `tb_bonded_serial_tx_parallel_rx`: byte-serial TX is packed into compact
  32-bit words and consumed by the parallel RX.
- `tb_bonded_parallel_tx_serial_rx`: parallel TX words are unpacked into
  byte-stream transfers for the byte-serial RX.
- `tb_bonded_parallel_loopback`: parallel TX connects directly to parallel RX.

Each sends a three-byte payload and checks the recovered bytes and packet/frame
metadata. These tests are included in the RTL GitHub Actions job. Together with
the existing byte-serial TX/RX tests, this establishes the intended four-way
compatibility test structure.

The testbenches are committed but have not yet been executed in an available
simulator. Their inclusion in CI is not evidence of a passing result; inspect
the GitHub Actions job output after the branch push.


## Receiver robustness coverage

The parallel RX width-matrix regression now exercises, at 8, 16 and 32 bits:

- A valid seven-byte DATA frame with dynamic lane ID `0xA5`, proving the
  parser is not restricted to the initial two-lane prototype.
- A corrupted frame CRC, which must set `frame_error` and release no payload.
- A frame from a different session, which must be discarded without treating
  stale traffic as physical-link corruption.
- An unexpected frame sequence, which must set `frame_error` and release no payload.
- Reset while a validated payload is stalled, which must flush the pending
  payload and return the receiver to idle.

Both byte-serial and parallel receivers now accept the full eight-bit lane-ID
field when configured for dynamic lane checking. These are source-level
regressions registered in CI; they remain unverified until the Icarus job
actually runs and its logs are inspected.
